## DNS and TCP on Android 17

The supervised suite verified and installed `wasmer.io/python/python@3.13.20`.
The interface created a test-owned Python application and imported its
fixture into a named volume using Android's document picker. The guest
used `example.com` for public DNS, a numeric public address for TCP, and a
private DNS answer that resolved to the second emulator's Wi-Fi address.
The peer served a known 27-byte HTTP body on the shared virtual Wi-Fi.

| Guest permissions | Public DNS and TCP | Private DNS and TCP |
| --- | --- | --- |
| Internet only, with Android LAN permission denied and again with it granted | Public name resolved, TCP connected | Private name unavailable, TCP denied |
| LAN only, Android LAN permission granted | Public name unavailable, TCP denied | Expected private name resolved. HTTP 200 with all 27 bytes, 32 ms from request write to body receipt, and `socket.settimeout(6.0)` still set. |
| Both guest permissions off, Android LAN permission granted | Public name unavailable, TCP denied | Private name unavailable, TCP denied |

Refusing the Android permission left the guest LAN save button disabled.
Granting it returned to the guest review, which still required an explicit
Save. The test verified the precise enabled state on the Compose button's
clickable accessibility node. The timed HTTP fixture was replayed after
adding the missing response-header read to the test script.

## Sharing over Wi-Fi on Android 17

The share was opened from **My apps** with both guest permissions off.
The Android local network permission was granted. The dialog displayed
the selected private address and accessible QR code. A separate Android 17
emulator on the same virtual Wi-Fi fetched HTTP 200 and the Python fixture
from that address. Disconnecting Wi-Fi removed the advertised QR and
stopped peer access. Reconnection left sharing off. Starting a new share
restored access, and **Stop sharing** removed it again.

Revoking the Android local network permission while an explicit share
was active made the prior address unreachable from the peer. The test
recorded the revoked grant after the system action. The main and peer
emulators used Android Emulator 36.5.11's shared virtual Wi-Fi. [Interconnecting emulator instances](https://developer.android.com/studio/run/emulator-networking-interconnect)
